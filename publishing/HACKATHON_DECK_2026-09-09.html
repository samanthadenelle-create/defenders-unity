01 — The problem

Mobile web3 gaming has an empty-stadium problem

The catalog is full of extraction-first apps with no game underneath. Players arrive for a token, find nothing to do, and leave. The wallet is the product and the game is the wrapper.

What a store like this is actually short of is the ordinary thing: a game somebody wants to open on the bus. Build that first — then the chain has something to attach to.

Our position: fun-first, crypto as a swappable rail. Nothing on the chain makes you stronger than a player who never connects a wallet.

02 — The game

One loop, four turns

You defend the Heart of Elarion — a world-tree at the centre of a dying realm. Combat feeds the economy, the economy funds the stronghold, the stronghold lets you fight deeper.

TURN I Fight

Real-time action combat. Four classes, talent trees that reach a castable ability on the first point.

TURN II Harvest

Echoes — the awakened essences of the people the tree guards — gather while you play and while you are away.

TURN III Build

A fully player-placed town: storefronts, defenses, walls, queues for building, training and research.

TURN IV Raid

Take the fight out to camps and enemy bases. Heartfire gates the raids; every camp states what it pays.

04 — Mobile engineering

What the Android work actually was

  • Two store variants from one tree. The dApp Store artifact compiles the Solana and SKR modules in; the Google Play artifact compiles them out entirely — not runtime-gated, so the strings never reach the binary. A packaging gate fails the build if that isolation breaks.
  • Mobile Wallet Adapter sign-in with session persistence. Sign in once, stay signed in for the day; the wallet is only re-asked at a purchase or a code redemption. Key material never touches game code.
  • Manage rebuilt for a phone. Nine full-screen pages, buildings as picture cards, a queue drawer, pick-up-and-move for placed structures, a 112 px touch-target floor.
  • Content served from a CDN, not packed in the APK — with a parity gate that blocks any release whose bundles were never uploaded.
  • Cloud save keyed to the connected wallet, with guest device saves carrying over on first connect.
  • A live capture harness for on-device crash and softlock triage, used every session.
05 — SKR

We read your stake. We never hold your SKR.

SKR is Solana Mobile's token, not ours. We do not mint it, do not custody it, and keep no withdrawable in-game SKR balance. It shows up in the game two ways, both non-custodial.

I. Native staking, read-only

The game queries the real SKR staking program for the player's active stake — program SKRskrmtL83pcL4YqLWt6iPefDqwXQWHSw9S9vz94BZ, with the stake-config and guardian-pool accounts and PDA seeds taken from Solana Mobile's own skr-staking sample and decoded against its published IDL layout. The connected wallet address is used only as a lookup key: no signature, no transfer, no custody. Tiers are cumulative, and the whole table is authored data we can tune without a code change.

Deliberately small — cosmetic and flavour only. A CI covenant gate fails the build if a stake reward stops being cosmetic.

II. SKR as a payment rail

Every support pack carries a real SKR price beside SOL and USDC, so a player holding SKR pays in SKR natively on the dApp Store build — where the platform takes 0%. That is exactly why SKR is the currency we convert to. Signing routes through MWA and Seed Vault; the game builds a transaction only for an explicit purchase.

06 — The covenant

Three lines we wrote into the build, not the pitch

Never pay-to-win

Chain-derived rewards are cosmetic or flavour. A player who never connects a wallet is never behind one who does. Enforced by a gate, not a promise.

Never custodial

You stake natively with Solana Mobile. We read. There is no in-game SKR ledger to drain, because there is no in-game SKR ledger.

Never a hidden crypto app

The Play build has the crypto surfaces compiled out of the binary; the dApp Store build has them compiled in. Each store gets an honest artifact.

07 — Under the hood

Built to keep shipping

  • Unity 6, IL2CPP/ARM64, twenty-plus assemblies on enforced dependency boundaries.
  • Data-driven design — balance, tiers, packs and waves are authored JSON with schema tests, so tuning is not a code change.
  • Instrumented, not guessed — a permanent flow-trace layer plus an on-device capture harness; frame-cost scopes name the dominant cost in milliseconds.
  • Gated releases — compile, regression suites, UI capture and content parity all have to be green on a fresh log before a build reaches a device.
  • Backend — serverless save/auth with a wallet-keyed player id and cloud carry-over.
  • Public repository, with the same gates in the tree the judges can read.
